Принцип 1 / 3

Запретить прозу

План — это слоты, где должна стоять цитата из источника: путь к токену, имя модуля, endpoint.

Слот пуст — план не проходит.
Проза скрывает пробелы. Схема их обнажает.

## structured_plan.md api_token: ~/.secrets/provider_token.txt existing_module: services/telephony/bridge.py endpoint: [ПУСТО] → GATE: FAIL
хакку.ии | бИИзнес08
Принцип 2 / 3

Ревьюер ≠ автор

Gate — всегда новый агент с чистым контекстом. Автор «влюблён» в свой план и проверяет его сквозь пальцы — ровно как человек.

Свежий контекст = свежий взгляд. Самопроверка в том же чате не работает.

GATE-A · независимый прогон [UI-1] полнота плана PASS [UI-2] покрытие разведки PASS [UI-3] ресурсы в слотах FAIL → план вернулся Architect → 2× FAIL → человек

Чтобы не наступить на чужие грабли

Три паттерна мульти-агентности

✕ Ловушка
«Команда агентов общается сама»
Persistent-агенты, координация сообщениями. Тонут в overhead: у людей есть общий контекст и дедлайны, у LLM — нет. Реальный кейс знакомого: половина подписки за неделю, 0 merged PR.
✓ Работает
Один агент + инструменты
Персональный ассистент: skills, cron, мессенджеры. State в одном месте, нулевой overhead координации. Для фоновых операций — да; для большой разработки — мало.
✓ Для разработки
Оркестратор + эфемерные агенты + типизированные артефакты
Агент живёт одну фазу, передаёт дальше не «чат», а артефакт со схемой. Crash на любой фазе — продолжаем с того же места. Это и есть /dev-team.

Забрать с собой
Процесс > промпт
Управляйте AI как командой, а не как автокомплитом. Хороший процесс прощает среднюю модель; плохой — губит лучшую.
Схема > проза
Слоты с цитатами из источника вместо свободного плана. Пустой слот виден, пропуск в прозе — нет.
Свежий контекст > самопроверка
Ревьюер — всегда отдельный агент с чистым контекстом. PASS / FAIL, два фейла — к человеку.
Память > повторение
Ретро записывается, а не вспоминается. Каждый фейл становится правилом для следующих сессий.
