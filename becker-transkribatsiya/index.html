Виктор · технический слой

«Какую архитектуру использовать?»

whisperX ставит диаризацию, но «больно медленный» локально. Нужны: встречи с диктофона, звонки, и realtime — голосом общаться с Telegram-ботом, который дальше работает с Claude API.

Валентина · организационный слой

«Раскатать на всех без Plaud на каждого?»

На уровне организации важно быстрее формировать итоги встреч и запускать follow-up: планёрка → обсуждения / вопросы / задачи → перенос в Битрикс24 (рабочие чаты + постановка задач сразу).

Главная мысль сразу: Plaud — это гаджет per-seat (микрофон + чужой Whisper + GPT в облаке США). Покупать его на каждое подразделение незачем — тот же результат разворачивается одним централизованным сервисом, а у Битрикс24 он уже встроен.
Архитектура · для Виктора

Из чего вообще состоит «расшифровка с задачами»

Любое решение — это цепочка из 3–4 слоёв. Понимание слоёв снимает вопрос «что выбрать»: вы выбираете не продукт, а где провести границу «своё / готовое».

1

STT — распознавание речи в текст

Движок: Whisper (локально / API), Deepgram, Яндекс SpeechKit, Сбер SaluteSpeech. Здесь же выбор облако vs локально и резидентность данных.

2

Диаризация — «кто говорил»

Разделение по спикерам. whisperX делает её через pyannote — и именно pyannote тормозит, не сама расшифровка. Часть движков (Deepgram, Яндекс, mymeet) дают диаризацию из коробки и быстрее.

3

LLM-слой — саммари, вопросы, задачи

Поверх транскрипта модель (Claude / GPT) выделяет договорённости, вопросы и action items. Это просто промпт. Plaud и mymeet делают ровно это, только упаковано.

4

Доставка — в Битрикс24

Задачи и итоги уходят в Б24: задачи, чек-листы, сообщения в рабочие чаты, обновление полей сделки. Нативно это умеет только Битрикс24 CoPilot; остальное — через коннектор или свой клей на Б24 REST API.

Про скорость whisperX: он медленный по двум причинам — диаризация pyannote тяжёлая и сам он не заточен под Apple Metal. На Mac быстрый путь — whisper.cpp + модель large-v3-turbo с Metal (≈28× реалтайма, час за пару минут), либо whisperX на MLX-бэкенде. Диаризацию тогда вешать отдельным проходом pyannote или уходить в облако.

Ключевое для Валентины

Кто реально ставит задачи в Битрикс24

Это и есть водораздел. Большинство инструментов останавливаются на красивом транскрипте — а вам нужно, чтобы задачи сами оказались в Б24 и рабочих чатах. Так умеют трое:

01

Битрикс24 CoPilot

Нативно. Расшифровывает звонки и видеовстречи, делит по спикерам, на русском. CoPilot Follow-up по видеозвонкам: повестка, итоги, тайминг → в чат, авто-создание задач и чек-листов, предложение обновить поля сделки. Данные не выходят из Б24.

02

mymeet.ai + Albato

mymeet сам выделяет задачи и брифы (РФ-хостинг, 152-ФЗ), а перенос в Б24 настраивается no-code-коннектором Albato. Хорошо для встреч в Zoom / Meet / Телемост, которых нет внутри Б24.

03

Свой контур

STT-движок (Яндекс / Сбер / локальный Whisper) + LLM-экстрактор задач + запись в Б24 через REST API. Максимум контроля и приватности, любые правила постановки задач — но это разработка, а не покупка.

Важный нюанс: CoPilot закрывает встречи и звонки внутри Битрикс24. Если планёрки идут в Zoom / Телемост / офлайн с диктофона — нужен либо бот (mymeet), либо свой контур, который донесёт результат до Б24.

Realtime · для Виктора

Голосовой Telegram-бот с Claude

Отдельная от транскрибации история — стандартный стек voice → STT → LLM → TTS. Голосовое в Telegram → распознавание (Deepgram streaming или локальный Whisper) → Claude API формирует ответ → ответ текстом или озвучка обратно через TTS. Собирается за вечер; для realtime-диалога важна низкая задержка STT, поэтому здесь облачный потоковый движок предпочтительнее локального. Готов скинуть скелет.
